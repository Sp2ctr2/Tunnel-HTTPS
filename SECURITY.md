# Security Policy

Tunnel HTTPS processes network metadata on an Android device. A security report should avoid exposing real user traffic or personal information.

## Reporting a vulnerability

Do not open a public issue for an exploitable vulnerability. Use GitHub's private vulnerability reporting or a private message to the repository owner and request a secure reporting channel. Include only the minimum reproduction details needed to investigate.

Please include:

- affected version or commit;
- Android version and device class;
- a concise impact description;
- reproduction steps that use synthetic domains or test data;
- a proposed mitigation, if known.

Do not include private DNS names, browsing history, packet captures, credentials, signing material, or personal network identifiers.

## Scope

Reports involving VpnService lifecycle, disclosure/consent behavior, WebView/native bridge exposure, DNS validation, packet parsing, resource exhaustion, credential handling, or release artifacts are in scope.

This policy does not promise a response time or a bug bounty. The project is experimental and does not claim anonymity, perfect privacy, or universal network compatibility.
