Android / VpnService / TUN

The network path, closer to the device.

Tunnel HTTPS is a local Android networking engine. It handles packet policy, DNS validation, selected transport logic, and connection strategy on the device, without a developer-operated remote VPN gateway.

01 / systems

More than a VPN screen.

The Android app is the visible edge of a larger local packet-processing system. The interesting work lives below the connect button.

01

Packets

IPv4 and IPv6 normalization, bounded fragment handling, checksums, and ICMPv6 policies.

02

Names

DNS parsing, response validation, caching, encrypted resolution, DNS64, and NAT64.

03

Flows

Local TCP and UDP relay paths with resource limits, cleanup, and network handover state.

04

TLS ClientHello handling, QUIC classification, contextual Turbo policy, and Aegis shadow inference.

02 / boundaries

Clear lines matter.

The repository owns policy and packet decisions. Android and the underlying network still provide the platform sockets and cryptography.

Implemented here

  • Packet normalization and validation
  • DNS policy, cache, and resolver strategy
  • Bounded local relay state
  • TLS metadata and fragmentation strategy
  • Learning policies and safety fallbacks

Provided by Android

  • VpnService and the TUN interface
  • Upstream kernel TCP sockets
  • HTTPS transport and TLS cryptography
  • Device networking and lifecycle signals

IPv4 packet pathSupportedValidation and normalization are bounded.

AegisShadowThe neural policy observes and does not control routing.

04 / evidence

Read the proof.

Source, tests, and dated reports are the way to evaluate the project. Claims should stay close to the code that supports them.

A skeptical engineer should be able to follow a packet from the TUN interface to the upstream socket, then find the test or limitation that explains each decision.
